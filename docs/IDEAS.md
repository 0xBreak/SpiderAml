- SpiderSend for several tokens behind an allowlist instead of one deployment per token.
- Registry owner → Safe multisig before any mainnet deployment.
- Tron registry via TronBox once there is a Tron integrator who would read it.

- Chainabuse (needs a key) and MistTrack / SlowMist (needs a key, check the terms) as extra live sources. Scraping Etherscan pages is out: their terms forbid it and the label API is paid.

- Litestream backup of the SQLite file to R2/B2 when deployed.

## Data and accuracy (2026-10-29)

- **Ransomwhere** (ransomware payment addresses, mostly Bitcoin): free, access by approved application; OpenSanctions mirrors it, but check that licence first (non-commercial vs the paid services on the roadmap).
- **Bitcoin checks, what is left.** Steps 1 and 2 are done (validation, labels, counterparties of the last 25 transactions via mempool.space / Blockstream). Left: balance and history on the page, and step 3 (large): common-input clustering.
- **Deeper tracing.** Counterparties two or three hops away with a falling weight, share of received funds coming from flagged addresses, known mixer and bridge contracts as a separate signal, interaction with known drainer contracts. Watch the RPC load and cost.
- **Arkham is not a data source:** no free API and no published licence, so no copying or scraping its labels. At most a "view on Arkham" link next to an address.
- Stablecoin freezes on Base, Optimism and Avalanche (Etherscan's free plan does not cover these chains, and our QuickNode plan reads logs in windows of 10,000 blocks, too small for a full history there). A paid Etherscan plan or a plan with wider log ranges would add them.
- Token score: a note when DEX liquidity is negligible (needs a new context code in the data layer).
- **Check a link / website (phishing domains).** People are usually sent a link, not an address. Paste a URL, get "this site is in phishing lists". Candidate lists: ScamSniffer `blacklist/all.json` (about 360,000 domains, updated daily, but GPL-3.0: read the licence before use in paid services), MyEtherWallet `urls-darklist.json` (MIT), MetaMask `eth-phishing-detect` (licence not stated on the repo page: check). Needs a new table and page; match on the registered domain and its subdomains, show source and date. Start with the MIT list.
- **Strict address checks for imports.** Checksums (EIP-55, Tron, Bitcoin) are verified on checks already; imported lists could be validated the same way before they are stored, and duplicates merged across sources (an outside review suggested it).
- **Sanctions cross-check with Chainalysis's on-chain oracle** as an independent test of our OFAC import (not as a label source). Terms and addresses per chain are not verified yet.
- **Regulatory and enforcement notices as a separate signal (2026-11-08).** Events that are not sanctions listings, for example the FinCEN section 9714 order against MEXC (2026-11-06: banks barred from moving funds for the exchange, no OFAC designation, no addresses listed). Today such an exchange stays at 0 and the page says nothing. Idea: a neutral note with date and source on the check page, kept apart from the score. Needs primary sources (FinCEN, Federal Register, OFAC, FIU notices), a way to tie a notice to an entity and its known addresses, and a rule that a note is never worded as a sanction.
- **Counterparty exposure from critical wallets (2026-11-09).** Instead of reading an address's history on every check (costs Zerion quota), precompute: take critical addresses (OFAC-listed, Tornado Cash pools, hacker and theft wallets such as Lazarus and the FTX drain), harvest their direct counterparties once a day and store them as derived labels ("received from X", "sent to X"). A check stays a plain lookup. Notes: plain RPC has no address history, so use `eth_getLogs` for pool events and token transfers (the address is indexed) and Etherscan `txlist` for native ETH; Tron and Bitcoin need their own sources, start with Ethereum. Weigh only meaningful contacts (sanctioned, hack, mixer), never exchanges (millions of counterparties); filter dust by amount and keep the direction (address poisoning sprays dust to create fake links); a mixer deposit is "interacted with a mixer", never "linked to a hack". Pilot first on a local copy: sanctioned addresses from our DB plus Tornado pools, measure matches and false positives before showing anything on the site. QuickNode check (2026-11-09): 2.8M of 80M credits used this month, so a daily harvest fits; the Build plan is $0 only through a hackathon coupon, check when it ends. QuickNode's SQL Explorer and Streams might replace some of the log scanning. Same family as "Deeper tracing" above.
- **Address dossier: OSINT sweep for one address (2026-11-09, SpiderFoot-style).** Enter an address and a network, the tool searches open sources for mentions and writes a Markdown report with evidence: our own hits, web search for the exact address string (news, forums, Reddit, BitcoinTalk, GitHub scam lists, security-team posts), public scam-report databases, explorer labels. Each mention is stored with the URL, date, the snippet around the address and an archive copy link (web.archive.org) so the proof outlives the page. Start as an owner-only CLI/TUI (`bun run dossier <address> [network]`), later an owner-only Telegram command (not public: search quota and abuse). Rules: a mention is not guilt (an address inside a list, or a victim named in a post, is not an accusation), so the report words it neutrally ("mentioned in"), groups by source and never turns into a score by itself; everything fetched is untrusted data (no running of content, no letting a model's summary become a published claim without a human check). Needs: a search API with a free tier (Brave Search or similar, key in `.env`; Google has no usable free API), a GitHub token for code search, per-source rate limits and a cache. Check licences and terms of each source before storing snippets.
- **Counterparty providers with fallback (2026-11-09).** One chain instead of Zerion alone: Etherscan (`txlist`/`tokentx`) → Alchemy (`alchemy_getAssetTransfers`, real address history on many EVM chains, free tier) → Zerion → QuickNode only if its Blockbook / Token API add-on is on the plan (plain RPC has no address history). Each provider returns the same `Counterparties` shape; a provider that fails or runs out of quota is skipped for some minutes (circuit breaker), the answer is cached, the check says which provider answered, and the ops panel reports a provider that stays down. Etherscan's free plan does not cover Base, Optimism or Avalanche, so those chains start at Alchemy. Needs `ALCHEMY_API_KEY` in `.env`.
- **Dossier inside the check (update to the dossier idea above).** For a medium or critical result the check page offers "Mentions in news and other services": search-API snippets only (we never fetch arbitrary pages on the server), cached per address for days, with archive links, shown in the page and in a PDF. Only trusted sources (security firms, regulators, big news) may add to the score, at most +10, and only to confirm something already flagged, never to create a risk from a keyword match. Mentions are worded neutrally; a mention is not guilt.
- **Wallet behaviour signals (2026-11-09).** (1) *Young wallet with a large turnover:* age under 6 months, turnover above 1M USD and a near-zero balance (inflow about equal to outflow), all three together, small score (10–15), never alone. Age needs the first transaction (one extra call sorted ascending). (2) *Source of the first funding:* the first meaningful incoming transfer (skip gas dust, from about 0.01 ETH) and who sent it. Exchange: a note only ("first funded by Binance"). Mixer, sanctioned, exploit, scam: scored by the existing link table. Bridge or DEX: a note and at most +5, because many honest users arrive that way. An unknown source is neutral, our exchange labels are incomplete. ENS is shown for readability and never scored (scammers buy it too). Plain turnover alone is not scored.
- **THORChain and other cross-chain swaps as context (2026-11-09).** Laundering through THORChain has been common lately (the Bybit hack, 2025), but it is also used for ordinary swaps. Find the router and vault addresses, mark them as context ("transfer through THORChain") with a small score, not like a mixer.
- **Local Sourcify archive and an own comparison backend (2026-11-12).** The whole Sourcify Parquet export (about 138 GB, 60M deployment rows, daily updates, no licence stated on the page, so check before any redistribution) is kept on the owner's disk (`~/SPIDERFILE/archive/sourcify/`, refreshed with `sync.py`). With it a local backend with an API can answer without the server: who deployed a contract, what a contract is called, its function signatures. First use found 101,253 of our addresses as deployers and 161,481 verified contracts that are already in our graph (378 of 882 unidentified hubs among them).
- **Creator graph (2026-11-12).** The creator of a flagged contract is a new suspect address, and a flagged address's other contracts are new nodes: creator -> contracts -> creators. First seeds: 576 creators of flagged contracts and 1,102 creators of weakly flagged ones (transfer history collected), 645 flagged addresses that deployed 3,375 verified contracts.
- **Fake and flash tokens from contract data (2026-11-12).** A contract named like a well-known token (`TetherToken`, `USDT`, `FiatToken`) at an address that is not the official one is a candidate fake (flash USDT); compare function signatures for scam patterns (blacklist, tax, honeypot). Covers verified contracts only, so it complements the token analysis and does not replace it.
- **Second generation by rule (2026-11-12).** Every address that scores 60+ only through its own links (94,498 found, mostly Tornado users) gets a derived label "indirect exposure" with a weight of about a third of its own score, at most about 25 (like the unidentified-hub label), so that the third generation (their counterparties) shows in a check. Names and risk flags from searches are for quality on the important cases, they cannot cover that mass (a month of Brave quota checks about 850 addresses, 6% of the 14,416 collected).
- **GoPlus as a confirming or lowering signal (2026-11-12).** GoPlus address security flags (stealing attack, blacklist, phishing) are stored raw per address. Calibrate on addresses whose truth we know (known bad against exchanges and tokens) before using them. First sample: any flag on 67% of known-bad and 0% of known-good addresses, the "stealing_attack" flag alone fires on about 30% of the second generation, so it is a reason for a medium label, not proof. A confirmed pair (a GoPlus flag plus a mention in an open source) is the strong case (163 of 840 in the first run). The first run was partly rate limited (HTTP 200 with code 4029): only code 1 counts as an answer, pace 2.6 s.
- **Research lists as real labels (2026-11-12).** Addresses in the public research list on Lazarus/BlueNoroff (74-80 of the first 840 second-generation addresses, mostly Tornado depositors of the Ronin bridge theft) deserve an exploit label of high severity, not the weak one. Other GitHub hits are mostly noise from machine-learning datasets and stay in the dossier only. A post by a security firm that calls an address an "attacker" goes to a review file, because it can also name a victim.
- **Other sources checked (2026-11-12).** Dune: the free plan is view-only, API needs a paid plan. Google BigQuery public datasets (chain data for Tron, Arbitrum, Polygon, Optimism, Avalanche, no labels): our free monthly quota is spent, retry next month with a dry run first. OLI labels (Open Labels Initiative): readable without a key through the public EAS GraphQL on Base (1.2M attestations of schema v1), but they name contracts and projects, not wallets (5 of 50 unidentified hubs, 0 of 50 wallets). Brave: free plan is a $5 prepaid credit, about 1,000 requests a month. GitHub code search: 10 requests a minute (not the 5,000 an hour of the ordinary API). web3.bio and Blockscout work without a key but add few names (31 and 34 of 840). Not verified: Elliptic++ and BABD-13 (Bitcoin address datasets), open exchange address lists in the Dune spellbook repository.
- **Tornado beyond the four ETH pools (2026-11-12).** The ERC20 pools (DAI, USDC, USDT, WBTC, cDAI, cUSDC) are collected (16,512 deposits, about 5% of the ETH volume; 9 of the 23 contracts from the OFAC list have no events), the loader does not read them yet (it knows ETH denominations only). Pools on Arbitrum, Polygon, Avalanche and BNB are not collected.
- **Wording and display (2026-11-12).** Label texts without the names of the services whose lists we read (done in `publicLabel`, a stored label stays as it came). Token analysis: a score marked "incomplete" for a big token reads oddly (PEPE 0/100), a token that barely trades needs its own status instead of "low risk", and the level scale should read "technical risk". The /whales and /token pages colour a sale red like a danger.
- **Contract names from Sourcify as signals and as labels (2026-11-12).** 3,989 of 3,991 asked contracts got a name (flagged 1,713, created by flagged addresses 1,485, second generation 414, unidentified hubs 377 of 378). Template names of scam contracts show up among our flagged ones: `YourToken` (94), `SecurityUpdates` (78), `ClaimContract` (44), `BatchTransfer` (45), `ClaimRewards` (40), `ClaimAirdrops` (33), and fake Tether copies named `USDT`, `BEP20USDT`, `TetherUSD`, `TetherToken`, `Tether`: a name list like that can flag contracts we do not know yet. Many hub names are empty of meaning (`BasicContract`, `AdminUpgradeableProxy`, `Airdropper`), so a name alone must not turn a hub into "infrastructure": only meaningful names (router, factory, pool, vault) may. **Pitfall before any label is written:** `isServiceAddress` treats an `info` label containing the word `contract` (SERVICE_WORDS) as a service and then skips the link score of that address, so an info label with a contract name on a flagged contract would remove its counterparty score. Change that check (an info label never exempts an address that also carries a severity 2+ label) before loading names as labels.
- **Services page (2026-11-12).** A "Services" section on the site, in both languages like the support page, with an enquiry by Telegram or a form (no online payment at first). Candidates, easiest first: (1) fund tracing for scam victims and projects after a hack (flow map, exchanges reached, an evidence pack for a freeze request or police); (2) an address or organisation dossier (our OSINT tool: neutral wording, sources, archive links); (3) token or project due diligence before listing or investing (our token analysis plus a human review); (4) bulk screening of an address file with reports; (5) consulting by the hour: blockchain, Solidity, AML; (6) an AML risk assessment of a service (exchange, exchanger, wallet, OTC), transaction-monitoring rules and sanctions screening setup; (7) a preliminary smart-contract review (no audit guarantees); (8) training for compliance teams; (9) later: a private API or integration, address monitoring with alerts (a subscription), private AML databases for a client (a long, expensive project). Before selling anything built on third-party data check each licence (Sourcify states none, explorer labels and Chainabuse have their own terms; Real-CATS is MIT). Wording: an informational report, not a legal conclusion and not an accusation; investigating people touches personal data and in some jurisdictions is a licensed activity. Needs a site PR (new GitHub token).

- **MBAL honeypot labels (2026-11-12).** The MBAL dataset (CC0, `dataset_10m_ads.csv`) tags ~198k Ethereum addresses "honeypot", but many carry entity names like metamask/uniswap, so the tag looks like a coarse contract heuristic. Not loaded. Plan (another day): verify them against several independent sources (GoPlus honeypot flag, Sourcify, token liquidity) and load only the confirmed part. Also not loaded: Bitcoin "sanctioned" (1.05M, cluster expansion; legacy addresses are stored lowercase so they cannot be matched) and exchange labels (270k, unverifiable origin).
